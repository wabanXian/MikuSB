# Progression mode local changes

This document tracks the local work to turn MikuSB from a full GM sandbox into a playable progression-oriented server.

## Sync baseline

- Fork remote: https://github.com/wabanXian/MikuSB.git
- Local branch: `codex/progression-mode`
- Baseline commit before progression work: `6eaf5fa README`

## Current implementation

### Config

`Common/Configuration/ConfigContainer.cs` now has:

- `ServerOption.GameMode`, defaulting to `Sandbox`.
- `Progression`, a new config section for progression-mode new player defaults.
- `Progression.PlayerLevel`, `PlayerExp`, `Vigor`, `Money`, `Gold`, and `Silver` for starting account state.
- `Progression.StarterCharacters` for explicit starter character GDPL entries.
- `Progression.StarterRewards` for GDPL reward rows granted on account creation.

`Sandbox` keeps the original behavior so existing GM-style usage is not broken. Set `ServerOption.GameMode` to `Progression` to use the new limited starter flow.

Example config shape:

```json
{
  "ServerOption": {
    "GameMode": "Progression"
  },
  "Progression": {
    "PlayerLevel": 1,
    "PlayerExp": 0,
    "Vigor": 120,
    "Money": 0,
    "Gold": 0,
    "Silver": 0,
    "StarterCharacters": [
      { "Genre": 1, "Detail": 1, "Particular": 1, "Level": 1, "Star": 1 }
    ],
    "StarterRewards": [
      [5, 4, 1, 1, 1000]
    ]
  }
}
```

### New player creation

`GameServer/Game/Player/PlayerInstance.cs` now branches new-player initialization by game mode:

- `Sandbox`: keeps the original all-characters, all-skins, all-supplies behavior.
- `Progression`: starts at the configured player level, grants starter characters, grants starter rewards through the existing `RewardManager`, and creates a default lineup from the starter roster.

`OnEnterGame` no longer auto-fills every supply item when `GameMode` is `Progression`.

Progression mode also skips the sandbox bootstrap that grants unlimited currency and full furniture unlock attributes. It explicitly syncs currency ids 1..200 to 0 before applying configured starter currency values, because some clients display fallback values when a currency attr is absent. New accounts set their default profile/home show girl to the first starter character via `SHOWITEM_GIRL`. The missing `PlayerSetting_ChangeAccountShowCard` API is implemented so the client can save account showcase card slots.

### Level clear rewards

`Progression.LevelClearRewards` can now grant extra GDPL rewards after successful level settlement. The hook uses the existing `RewardManager`, so extra rewards flow through the same inventory and sync code as native level rewards.

Example:

```json
{
  "Progression": {
    "LevelClearRewards": [
      {
        "LevelType": "Chapter",
        "LevelId": 100101,
        "FirstClearOnly": true,
        "Rewards": [
          [5, 4, 1, 1, 10]
        ]
      }
    ]
  }
}
```

The hook currently appends configured rewards as an additional settlement reward category and syncs the granted items to the client.

### Local runtime ignores

`.gitignore` now excludes local runtime data:

- `Config/Database/`
- `Resources/`
- `Resources.copy-before-link*/`
- `Config/Logs/`

These files are generated by local runs or resource downloads and should not be committed.

## 2026-09-25 follow-up

- Added `RandomShowGirl_Set` so the random home-display panel no longer reports a missing handler. In progression mode new accounts seed the random display list from the starter roster only, which keeps the home random pool on the default low-level characters instead of the sandbox all-character set.
- Added `Activity_Flag` as a lightweight persisted activity flag handler for the showcase/activity presentation requests.
- Added `Progression.RestrictMainChapterProgression` and `Progression.MainChapterLevelLimit` configuration. The default progression gate allows the first ordered main-chapter level, then requires the previous level to have a pass count before entering the next one, capped to 10 levels by default.

Testing note: close the running server process before a full `dotnet build`, because Windows keeps `MikuSB.dll` locked while the service is running. Use a fresh account or clear that account database row when checking starter/random-show defaults.

## 2026-09-25 prologue entry follow-up

- Added `Chapter_NewPrologueEnterLevel` for the story screen path used by the current client. It validates the chapter level with the same progression gate as `Chapter_EnterLevel`, creates a level session, and returns an `nSeed` response.
- Added small missing-log handlers for `Launch_OnCloseLoadingLog`, `FavMailLog`, and `Chapter_LevelFail` so normal loading, mail telemetry, and failed stage exits no longer report missing CallGS handlers.
